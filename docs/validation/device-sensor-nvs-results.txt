2026-10-27 — ESP32-S3, isolated simulation image

The simulation image uses fake probes and a separate `monitor_sim` sensor
settings namespace. `device_sensor_test.py` verified authenticated settings
updates, invalid/stale updates, calibration/alert behavior, disabling without a
fabricated temperature, and a state event. After an esptool reset,
`--verify-reboot` confirmed the ROM-keyed sensor settings persisted.

Host settings codec tests cover version and checksum validation, every-byte
corruption, truncation, unknown versions, duplicate identities, size limits,
settings validation and reconstruction against stable ROM IDs. Device settings
are committed as one NVS blob; unknown/corrupt device preferences are retained
read-only. No physical probe or LCD was enabled.

The normal firmware was restored and passed a 15-second bare-board USB smoke:
READY, zero sensors, disabled bus/LCD, healthy history, expected 5-second
health cadence and no panic. The simulation image was not left on the board.

## 2026-10-27 — expanded two-ROM reboot acceptance

Rebuilt and flashed the isolated `firmware/build-sim` image with ESP-IDF v6.1.
`python tools/device_sensor_test.py --port /dev/ttyACM0` passed authenticated
sensor edits, input and revision rejection, per-ROM calibration and alert
behavior, disable/re-enable, and distinct labels/limits/calibration for two
ROM IDs. A protected system restart returned the simulation image to READY;
`python tools/device_sensor_test.py --port /dev/ttyACM0 --verify-reboot` then
confirmed both ROM configurations persisted independently. The test computes
the expected fake temperature from the ROM ordinal, so it does not depend on
display ordering. `python3 -m py_compile tools/device_sensor_test.py` passed.

The regular `firmware/build` image was restored and its 20-second
`tools/device_smoke.py --port /dev/ttyACM0 --seconds 20` passed: READY, zero
sensors, disabled sensor bus and LCD/backlight, healthy history, positive heap,
five-second health cadence and no panic. Neither the LCD nor probes were
connected. This verifies the device settings path with simulated providers;
it is not physical sensor evidence. TMS1 is the first settings schema, so there
is no older deployed format to migrate.
